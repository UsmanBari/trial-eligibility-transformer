      What this does

      For each eligibility criterion the fine-tuned model reads the numbered patient note and returns one label and the sentence numbers that support it, as JSON. The overall decision is a simple rule on top: any “not included” or “excluded” makes the patient likely ineligible; otherwise any “not enough information” means the case needs review.

      Model

      Qwen2.5-1.5B-Instruct with a class-balanced LoRA adapter (rank 16 on all attention and MLP projections, 18.5M trainable parameters), trained only on the 37 training patients of ncbi/TrialGPT-Criterion-Annotations and chosen on the 8 validation patients. GPT-4 outputs in the dataset were never used.

      Decoders

      • KV cache: our own decoding loop. The system prompt and patient note are encoded once and that cache is reused for every criterion, so only the criterion text is processed per criterion.
      • Speculative, prompt lookup: proposes the next tokens by copying from the prompt, and the target model checks them in one pass. Output is identical to normal greedy decoding.
      • Speculative, draft model: a fine-tuned Qwen2.5-0.5B proposes tokens. Also identical output, but it only pays off when the draft is much cheaper than the target.
      • No cache: recomputes everything for each new token. Kept only as the correctness reference.

      Limitations

      • Trained on 602 criterion annotations from 37 patients; test accuracy 72% and macro-F1 0.63 on 8 unseen patients.
      • The most common error is deciding a criterion when the note does not contain the information (“overconfident”).
      • Long notes are cut from the end to fit the input budget; the app warns when this happens.
      • Explanations quote the cited sentences; they are not a clinical justification.
